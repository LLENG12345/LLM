## 记录规则

- 每项可独立说明的功能变更或阶段结果追加一条，不必逐行或逐次工具调用记录。
- 区分代码改动、数据检查、模型训练和 Kaggle 提交；静态检查通过不等于训练成功，本地文件合法不等于有效提交。
- 写明具体文件、修改前后行为、实际执行的验证和结果；未执行项目直接注明。
- 数值结果必须关联运行 ID、配置、代码、数据和分折版本；未取得时写“未取得”，不以 0 或推测值代替。
- 实验失败、方案放弃、规则变化和验证限制也记录；历史结论被修正时追加说明。
- 尚未提交的改动写“未提交”，提交后可补引用；不能把旧 HEAD 当作新改动的提交号。
- 每次功能开发结束前同步本文件，阶段验收通过后再更新计划。大型原始日志、权重和缓存只链接到产物位置，不复制到本文。
