本文是比赛项目的持续开发计划，按代码构建依赖安排工作，不安排日历时间。先建立可信、可复现、可提交的基线，再根据实验决定是否引入新特征、预训练模型和融合。

计划版本：v1.1。最近核对：2026-11-19。原始基线：`116f486`；初轮开发起点：`77bb475`。实际进度与阶段结果见 [工作日志](工作日志.md)，数值实验摘要见 [experiments.csv](../experiments/experiments.csv)。

### 输入 评分与执行约束

官方数据页 O2 列出：训练集 2,699 条、150 个 prompt，字段为 `id, prompt_id, text, model`；测试输入只有 `id, text`，隐藏测试约 4,000 条，且 prompt 未在训练中出现。交互示例不能代表完整测试分布。

官方概览 O1 使用 Balanced Accuracy，即 18 类召回率的平均值；测试类别数量不等，公私榜模型比例也不同。O3 已读取说明为公榜约占测试集 40%，其余约 60% 用于最终结果。

工程上采用以下设计：按 prompt 隔离验证；预测特征仅依赖 `text`；比较整体折外分数、每类召回率及稳定性；根据实际测试行数预测，不硬编码为 3 或 4,000，不强制各类数量相等，也不假定隐藏测试每个 prompt 各模型恰好出现一次。

根据 O1，评分重跑 Notebook，读取 `/kaggle/input/competitions/name-that-llm/test.csv`，要求 `submission.parquet` 包含 `id, model`，每个测试 ID 一次，值非空且标签合法。CPU 或 GPU Notebook 限时 9 小时，互联网关闭；概览允许公开、免费外部数据和预训练模型。

实现将文件写到 `/kaggle/working/submission.parquet` 并回读校验。正式操作依据 O5 保存并完整运行 Notebook 版本，再从该版本提交。本地文件合法不等于已有有效比赛提交。

**待核实细则：**每日提交上限、最终候选数量、队伍上限、分享要求、收费资源与 API 生成数据的条件、获奖方案许可证和复现义务。讨论文档中提到的次数和人数暂不作为已确认规则。基础开发可继续；使用相关资源或安排正式发布前须核实对应条款。

### 迭代执行约定与版本里程碑

第一开发周期以可提交初版为目标，依次推进 S01—S06。每轮只实现明确任务，验证、验收、写日志后停止或进入下一轮；复用已有成果，失败、暂缓和路线变化保留记录。

S03 先满足输入完整性、固定分折和数据泄漏检查。S03-01 中更深入的近重复研究、S03-02 深入风格 EDA 可延后；S03-06 在初版阶段先定义复核策略，最终候选复核按需要执行，不阻塞 S04 基线训练。

S06 优先执行 S06-06、S06-07，用可靠的自包含基线跑通离线运行和首次有效提交，再逐步执行 S06-01、S06-02、S06-03、S06-04、S06-05。保留任务编号，重构后与原始基线进行结果一致性验证。最终 V1.0 需具备有效提交和必要的共用框架，不要求首次提交前完成全部自动化。

第二周期根据基线成绩、各类召回率、混淆矩阵、资源成本和 Kaggle 反馈选择 S07—S10，并非必须全部实施。每轮遵循：问题分析 → 改进假设 → 小范围实施 → 对照实验 → 结果分析 → 保留或回退 → 更新日志。

| 里程碑 | 验收含义 |
| --- | --- |
| V0.1 | 环境与数据路径可运行 |
| V0.2 | 输入契约与固定分折完成 |
| V0.3 | 取得真实基线成绩 |

里程碑不自动产生 Git Tag 或 GitHub Release。S06-B 最小公共框架及真实五折/全量/独立提交 Notebook 等价性检查均通过，首次评分 0.311 及保存版本 371057481 已由用户确认并归档，V1.0 达到。新生成的 Notebook 本轮未提交，不继承旧版公榜身份。远端环境、Rules、S01 已跟踪 CSV 和 S03 延后研究等限制继续保留，详见 L011。
